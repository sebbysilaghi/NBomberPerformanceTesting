# NBomber Performance Testing — C# / .NET / Playwright

![.NET 8](https://img.shields.io/badge/.NET-8.0-512BD4) ![NBomber 6.7.1](https://img.shields.io/badge/NBomber-6.7.1-blue) ![Playwright](https://img.shields.io/badge/Playwright-C%23-2EAD33) ![Target](https://img.shields.io/badge/load_target-localhost_only-green)

A reproducible **performance engineering portfolio project** using [NBomber](https://nbomber.com/), C#, ASP.NET Core and Playwright. It demonstrates workload models, instrumented API user journeys, real-browser interaction timing, response assertions and evidence-based reporting. The target is a **self-hosted demonstration application**; this repository does not stress public websites.

> **Evidence:** Four actual NBomber HTML reports captured on **23 November 2026**. All reported zero failed operations. See [results and interpretation](docs/results-analysis.md). Results are illustrative *local measurements*, not production SLAs or capacity claims.

## Test architecture

- **Local application:** ASP.NET Core minimal API + static browser UI at `http://127.0.0.1:5055`.
- **API workflow:** search for a mouse (`GET /api/products?q=mouse`); obtain a quote (`POST /api/quotes`), and validate result data.
- **Browser workflow:** load storefront; wait for product rendering; search for `mouse`; check result content.
- **Load profiles:** bounded smoke, steady concurrency, fixed-arrival burst. Browser workload is intentionally restricted to one concurrent user on the local machine.
- **Reliability:** Failures are returned when responses or business assertions are invalid; isolated Playwright browser contexts are disposed after iterations.

## Prerequisites

- .NET 8 SDK
- Playwright's Chromium browser (UI test only)
- PowerShell for the sample Playwright installation command

## Run locally

Start the local target (terminal 1):

```bash
dotnet run --project src/Portfolio.DemoApp
```

Verify `http://127.0.0.1:5055/health` and the homepage. In a second terminal:

```bash
dotnet run --project src/Portfolio.ApiLoadTests -- smoke
dotnet run --project src/Portfolio.ApiLoadTests -- steady
dotnet run --project src/Portfolio.ApiLoadTests -- burst
```

To run the real-browser test, first build and install Playwright Chromium:

```powershell
dotnet build src/Portfolio.UiLoadTests
pwsh src/Portfolio.UiLoadTests/bin/Debug/net8.0/playwright.ps1 install chromium
dotnet run --project src/Portfolio.UiLoadTests
```

The API and UI runners use fixed `127.0.0.1:5055` addresses to avoid accidentally load-testing unapproved third-party systems.

## Reporting and experimental validity

- NBomber reports can show throughput, percentile latency, successes, failures and per-step timing. This portfolio includes **original historical reports**, not numbers generated by CI.
- These demo runs used an in-memory app and loopback network; they cannot establish real-world production capacity.
- No formal SLA threshold was configured. **Zero failed operations** does not prove that a latency SLO has been met.
- The historical reports contain missing HTTP status-code and data-transfer metrics; see [analysis](docs/results-analysis.md). A planned follow-up is to instrument response metadata and define thresholds after several comparable baselines.
- **Important:** CI intentionally **compiles only**. No performance numbers are produced by shared GitHub-hosted runners.
